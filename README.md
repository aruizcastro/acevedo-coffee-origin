# Acevedo coffee origin

A static, bilingual (Spanish / English) website that tells the origin and traceability story of a specialty coffee grown in Acevedo, Huila (Colombia). A customer scans the QR code on the bag and sees the region, the farm, the producer and the details of the exact lot they bought.

Plain HTML + CSS + JavaScript. No framework, no build step — it runs on GitHub Pages as is.

## Structure

```
index.html            Home: hero, region, farm, process, lot list, contact
lot.html              Lot sheet: lot.html?id=ACV-2026-001
css/styles.css        All styles
js/common.js          Shared helpers (language switch, data loading, formatting)
js/home.js            Home page: farm details, lot list, map, contact
js/lot.js             Lot page: renders one lot and its QR code
data/farm.json        Brand, farm, producer and contact details  ← edit this
data/lots.json        One entry per lot                          ← edit this
img/                  Photos (placeholders to replace)
qr/                   Printable QR codes, generated by the script
scripts/generate-qr.js
```

## Before you publish

1. **Fill in `data/farm.json`.** Every value marked `[PENDIENTE: ...]` is a detail that still has to be provided. The site highlights them with a dashed outline so none is forgotten. Set `coordinates` to approximate numbers, e.g. `{ "lat": 1.80, "lon": -75.90 }` — until then the map shows Acevedo's town center.
2. **Replace the photos in `img/`**, keeping the same file names:

   | File | Used for | Suggested size |
   | --- | --- | --- |
   | `farm-hero.jpg` | Home hero | 1600 × 1000 |
   | `region-acevedo.jpg` | Region section | 1600 × 900 |
   | `farm.jpg` | Farm section | 1400 × 900 |
   | `producer.jpg` | Producer portrait | 900 × 1100 |
   | `lot-example-1.jpg`, `lot-example-2.jpg` | Sample lots | 1600 × 900 |

   Keep each photo under ~300 KB so the page stays fast on mobile data.
3. **Delete the two sample lots** in `data/lots.json` (they carry `"example": true` and are labelled EJEMPLO / EXAMPLE on the site) and add your real ones.
4. **Review the "Sources" links** in the footer of `index.html`. They point to each organisation's home page; swap in the specific articles you want to cite.

## Preview on your computer

The pages load the JSON files with `fetch`, which browsers block when a file is opened directly from disk. Start a small local server instead:

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000>.

## Publish on GitHub Pages

1. Create an empty repository on GitHub and push this folder to its `main` branch (commands below).
2. In the repository: **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to *Deploy from a branch*, **Branch** to `main` and the folder to `/ (root)`. Save.
4. After a minute or two the site is live at `https://USER.github.io/REPOSITORY/`.
5. Put that address in `"site_url"` in `data/farm.json`, then generate the QR codes.

```bash
git init -b main
git add .
git commit -m "Initial site"
git remote add origin https://github.com/USER/REPOSITORY.git
git push -u origin main
```

The empty `.nojekyll` file tells GitHub Pages to serve the files untouched.

## Add a new lot

Open `data/lots.json`, copy an existing block inside `"lots"` and change its values:

```json
{
  "id": "ACV-2026-003",
  "name": { "es": "Lavado La Esperanza", "en": "La Esperanza washed" },
  "harvest_date": "2026-10-12",
  "variety": "Caturra",
  "process": { "es": "Lavado", "en": "Washed" },
  "fermentation_days": 2,
  "drying": {
    "method": { "es": "Marquesina solar", "en": "Solar dryer" },
    "days": 15
  },
  "altitude_masl": 1680,
  "sca_score": 86,
  "tasting_notes": [
    { "es": "Chocolate", "en": "Chocolate" },
    { "es": "Frutos rojos", "en": "Red fruit" }
  ],
  "roast_date": "2026-11-20",
  "roast_level": { "es": "Medio", "en": "Medium" },
  "weight_g": 340,
  "photos": ["img/lot-ACV-2026-003.jpg"]
}
```

- `id` must be unique. It is the code printed on the bag and used in the link: `lot.html?id=ACV-2026-003`.
- Dates use `YYYY-MM-DD`.
- Any text field can be a plain string (shown as is in both languages) or `{ "es": "...", "en": "..." }`.
- `photos` is a list. The first one is the large photo; the rest appear as a gallery. A photo that is missing is simply skipped.
- Separate blocks with a comma, and check the file is still valid JSON (for example at <https://jsonlint.com>) — a missing comma stops every lot from loading.

Commit and push; the lot is live as soon as GitHub Pages redeploys.

```bash
git add data/lots.json img/
git commit -m "Add lot ACV-2026-003"
git push
```

## Generate the QR codes

Each lot page already shows its own QR code on screen. For print-quality files, use the script (requires [Node.js](https://nodejs.org)):

```bash
npm install
```

```bash
npm run qr
```

This writes `qr/<lot id>.png` (1200 px) and `qr/<lot id>.svg` for every lot, each pointing to `<site_url>/lot.html?id=<lot id>`.

- One lot only: `npm run qr -- ACV-2026-003`
- Different address without editing `farm.json`: `npm run qr -- --url=https://USER.github.io/REPOSITORY`

Always scan a printed proof with a phone before sending the bags to print. If the site address ever changes (new repository name, custom domain), regenerate and reprint the codes.

## Languages

The site opens in Spanish, or in English when the visitor's browser is set to English. The ES / EN switch in the header remembers the choice. To force a language in a link, add `&lang=en` or `&lang=es`.

Both languages live side by side in the HTML, marked with `lang="es"` and `lang="en"`; CSS hides the one that is not active. To edit a text, change both versions:

```html
<h3><span lang="es">Secado</span><span lang="en">Drying</span></h3>
```
